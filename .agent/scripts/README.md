# Scripts — 确定性 Agent 工具

> 这里存放**确定性脚本**，让 Agent（或人）可以跑它们来验证项目状态，而不是永远依赖
> Agent 自己的记忆。

**为什么需要这个目录：**

> **能用 Script / Test 确定性验证的规则，不应该永远依赖 Agent 自己记住。**

当一个检查是重复发生、定义清晰、值得可靠地执行时，它就会从
"Agent 应该记得做这件事"毕业成一段脚本。

**适合放在这里：**

- Spec 校验 —— 当前工作的 Feature Spec 是否存在、是否齐全。
- 项目检查 —— 仓库结构、命名约定、禁用模式。
- 架构检查 —— 强制执行 ADR 的护栏。
- 诊断脚本 —— `debug.md` 中会反复用到的可重复探针。

**不适合放在这里：**

- 长跑服务。
- 项目业务逻辑（等真正有源码树之后放那里）。
- 一次性 scratch 脚本 —— 只有真正被反复使用时才晋升进来。

**约定：**

- 每个脚本独立文件，命名清晰，例如 `check-specs.sh`、`check-structure.sh`。
- 脚本可以从仓库根目录运行，失败时退出码非零，并给出明确的错误信息。
- 每个脚本的用途写在文件顶部（检查什么、为什么、失败时怎么修）。
- 脚本保持 **Agent-neutral**：不得假设某个具体 Coding Agent。

等真的存在"需要被反复执行"的检查时，再加第一个脚本。不要预先建空脚本填目录。
